# BookMarker：Chromium 浏览器扩展实施方案

## 1. 总体架构与已确认选择

改为 **Manifest V3 扩展**，优先支持 Chrome、Edge，最低 Chromium 134。点击扩展图标，在独立标签页打开书签管理器。

- **操作立即生效**：直接读写当前浏览器配置中的书签，监听浏览器及其他扩展产生的变更。
- **无需本机服务**：使用 React＋TypeScript＋Vite 构建扩展页面；后台 Service Worker 负责书签操作和检测任务。
- **本地持久化**：IndexedDB 保存原文件、操作日志、快照、扩展元数据和检测结果；`chrome.storage.local` 保存设置。
- **代理方式**：检测使用浏览器适用于请求的网络配置，不单独设置或修改浏览器代理。
- **隐私范围**：扩展不上传书签，不使用云端数据库或 `storage.sync`。浏览器已有的书签同步仍由浏览器设置决定。
- **交付形式**：源码、可加载的 `dist/` 扩展目录、ZIP 包及 Chrome／Edge 安装说明；第一版不包含商店发布。

必要权限为 `bookmarks`、`storage`、`unlimitedStorage`、`alarms`；检测所需的网站访问和 `webRequest` 权限在首次启动检测时申请。拒绝检测权限仍可正常管理书签。

## 2. 书签管理与即时写入

**文件管理器界面**

左侧文件夹树，中间虚拟化列表，右侧详情面板；顶部提供面包屑、搜索、导入导出、新建和批量操作。

- 支持新建书签／文件夹、重命名、编辑 URL、右键菜单、拖拽移动及同目录排序。
- 支持勾选、Cmd/Ctrl 多选、Shift 连选，以及批量移动、删除和重命名。
- 批量重命名支持文字替换、前后缀、连续编号，提交前展示预览。
- 按名称或 URL 搜索，支持当前目录／全库范围，以及域名、类型、检测状态筛选；搜索结果可定位回原目录。
- 精确按完整 URL 检测重复，不忽略参数、锚点或协议。展示副本路径，由用户选择保留项，其余移入回收站。

**浏览器数据操作**

- 以 `chrome.bookmarks` 返回的数据为准，仅更新涉及的字段或节点，避免整库删除重建。
- 自动识别浏览器固定根目录、账号书签区域和受管理节点，不硬编码目录 ID。固定目录禁用重命名、移动和删除，受管理节点只读。[书签 API](https://developer.chrome.com/docs/extensions/reference/api/bookmarks)
- 后台串行执行修改命令，先记录操作意图，再调用浏览器 API，成功后确认实际结果。
- 批量操作逐步记录进度；发生错误时明确展示已完成项和失败项，不声称整批具有数据库事务原子性。
- 后台重启后先核对浏览器实际状态，再恢复未完成操作；无法确认的新建操作暂停核对，避免重复创建。
- 外部变更及时更新界面。提交前检查被操作节点是否仍符合预期，存在冲突时不覆盖外部修改。

## 3. 回收站、备份与格式兼容

**回收站与历史**

- 在来源顶层书签区域内按需建立可见的 **“BookMarker 回收站”**，删除实际执行移动，保留原节点。
- 记录原父目录和位置；恢复时移回。原父目录不存在时恢复到同一区域的可写目录并提示。
- 回收站内容默认排除在搜索、去重、检测和普通 HTML 导出之外。
- 永久删除和清空需要确认。普通删除可通过移回保留节点 ID；永久删除后重建无法恢复原 ID、创建时间及未公开元数据。
- 支持撤销、重做和版本回滚；只撤回能够确认由本工具造成的变更，遇到外部修改展示冲突。
- 每次操作保存日志，每 50 次操作及大型批量操作前建立快照；另保留最近 30 份每日快照。回滚生成新版本。

**导入与导出**

- 保留原方案的 Chrome／Edge／Firefox HTML、Chromium `Bookmarks` JSON、Firefox 未压缩 JSON 导入。
- 导入先解析预览，默认在所选目录新建导入文件夹，确认后写入浏览器；不提供一键清空整库式导入。
- 原文件按原始字节保存，保留未知字段、标签、图标和高精度数字；不能写入浏览器的字段保存在扩展元数据中。
- 导出通用 UTF-8 HTML，以及包含原文件、扩展元数据、历史和快照的完整项目 ZIP。
- 项目备份恢复先进入预览，再应用到浏览器；跨配置恢复按新建处理，不复用另一配置中的节点 ID。

**无损边界**：导入原文件可以完整保留；直接读取浏览器时，只能备份扩展 API 开放的数据。新建或更新 URL 后展示浏览器实际保存的值，同时在备份中保留原始输入。扩展内备份随卸载清除，下载的 ZIP 可独立保留。[本地存储说明](https://developer.chrome.com/docs/extensions/reference/api/storage)

## 4. 网页可达性检测

- 从扩展后台发起跨域请求，支持选中项、当前目录或全库检测；不注入网页脚本，不携带站点登录凭据。[扩展跨域请求](https://developer.chrome.com/docs/extensions/develop/concepts/network-requests)
- 默认并发 6，同主机最多 2；单次尝试超时 12 秒。先 HEAD，对方法不支持或可能误判的响应使用限量 GET 复核，最多读取 64 KiB。
- 展示进度、取消和失败项重测；结果包含检测时间、耗时、最终 URL、HTTP 状态及可观察到的重定向信息。
- 检测队列和完成结果持续落盘，按短批次执行，通过消息和 `alarms` 续跑；浏览器关闭后停止，重新打开后恢复未完成任务，不依赖后台永久存活。[Service Worker 生命周期](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle)
- 默认跳过明确的内网 IP、本机地址和已知内网域名，设置中可开启。纯扩展无法在请求前可靠识别所有域名的内网解析结果，因此不把该筛选描述为严格的网络隔离。
- `webRequest` 只处理本扩展检测任务对应的请求，保留浏览器提供的原始错误信息；无法获取时显示“未提供详细错误”，不编造错误码。

| 结果 | 显示内容 |
|---|---|
| 正常 | 2xx，以及可观察到的跳转信息。 |
| 站点响应错误 | 404、410、5xx 等实际 HTTP 状态。 |
| 访问受限 | 401、403、429，提示登录、权限或限流。 |
| 连接异常 | 原样显示浏览器网络错误，例如 `net::ERR_NAME_NOT_RESOLVED`。 |
| 无法确认 | 超时、请求失败但缺少详情，或检测结果不足以判断原因。 |
| 已跳过 | 内网筛选、非 HTTP/HTTPS 地址、缺少权限等原因。 |

错误信息只作为诊断证据和辅助说明，不作为自动删除依据；超时、DNS 或连接失败不能直接断定责任在本地网络还是目标站点。浏览器错误字符串可能随版本变化，需要保留原文和兜底处理。[webRequest 文档](https://developer.chrome.com/docs/extensions/reference/api/webRequest)

## 5. 内部接口与验收

**核心类型与消息**

- `BookmarkRecord`：浏览器节点 ID、父目录、顺序、标题、URL、只读状态及来源元数据引用。
- `OperationRecord`：操作 ID、涉及节点、修改前后数据、分步进度、执行状态和冲突信息。
- `CheckJob / CheckResult`：任务范围、权限状态、进度，以及节点 ID、被测 URL、HTTP 状态、原始错误、时间和耗时。
- 页面通过类型化 `chrome.runtime` 消息提交操作和读取状态，后台统一执行；URL 改变后旧检测结果标记过期。

**验收内容**

- 在独立测试配置中加载扩展，验证 Chrome／Edge 的创建、编辑、拖拽、批量操作及外部变更同步，不使用用户真实书签测试。
- 验证回收站移动和恢复保留节点 ID，固定目录和受管理节点无法被误操作。
- 验证中途失败、后台终止、浏览器重启后的操作核对和检测续跑，确保不重复创建或误删节点。
- 验证各格式的中文、特殊字符、空目录、未知字段和原文件校验值，以及 HTML 再导入和完整备份恢复。
- 使用受控服务验证 HTTP 错误、权限拒绝、超时、重定向、取消和缺少错误详情等情况。
- 使用一万条书签验证列表虚拟化、搜索响应和批量操作反馈。
- 完成类型检查、单元测试、扩展集成测试和生产构建，交付权限说明、安装说明及错误诊断说明。
