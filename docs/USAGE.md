# 使用与错误诊断

## 整理书签

左侧选择文件夹，点击列表项查看详情，双击打开书签或文件夹。勾选、Cmd/Ctrl 点击可多选，Shift 点击可连续选择。支持右键菜单、拖到文件夹移动，以及在当前目录中拖到书签上方排序。筛选视图不支持拖拽改变列表顺序；应先回到原目录。

「名称排序」会真正修改浏览器内的顺序。「批量重命名」支持按字面文字替换、前后缀、连续编号，提交前显示预览。所有修改立即生效。

搜索可使用名称或 URL 子串，选择全库或当前目录（含子目录），并按域名、类型、检测状态筛选。搜索结果的详情或右键菜单提供原目录定位。

重复书签按完整 URL 精确分组。`http` 与 `https`、不同参数、不同锚点都视为不同 URL。每组选择保留项后，其他副本进入对应区域的回收站。受管理副本所在的组不允许直接批量回收。

## 回收与版本

- 普通删除会将节点移动到来源顶层书签区域内按需创建的「BookMarker 回收站」。这是浏览器可见的真实文件夹。
- 恢复会使用保存的原父目录和位置，保留节点 ID。原目录丢失、不可写或仍在回收站时，恢复到同一区域的可写根目录，并显示提示。
- 永久删除和清空要求勾选确认。永久删除无法保留原 ID、创建时间及 API 未公开数据，因此没有“无损撤销”。
- 「操作与版本」逐步显示完成、失败、冲突、等待核对；批量操作不是数据库事务，不保证整批原子性。
- 撤销/重做由新的操作记录完成。撤销新建项会移入回收站，重做再移回，以保留节点 ID。
- 版本回滚逆序撤回快照之后本工具已确认的操作，不整库删除重建。外部修改会保留为冲突。
- 每 50 次完成操作、大型批次（20 步及以上）及永久删除/回滚前自动快照；每天另存一份，保留最近 30 份每日快照。手动快照和操作日志不自动清理。
- 当前修改尚未完成或等待核对时，下一次修改与手动快照会暂停提交，以维持清晰的版本边界。

## 中断后的核对

后台重启先读取未完成日志，再对照浏览器实际数据。

1. 更新/移动若已达到预期状态，记录为完成；若仍是修改前状态，可继续执行。
2. 无法确认的新建会显示「需要核对」，**不会自动再建一次**。查看该步骤的目标目录、标题、URL，并在详情查看可能对应节点的 ID。
3. 确实已创建时，输入该节点 ID 并选择「关联此节点」；后台仍会验证目录、标题和 URL。
4. 确认该步骤应跳过时，选择「核对后跳过」。跳过不会删除任何已有节点；依赖该目录的后续新建会明确失败。

不要用重复点击提交来代替核对。出现外部冲突时，先刷新并检查实际书签，再针对当前节点发起新的修改。

## 导入、备份与恢复

支持 Chrome/Edge/Firefox 导出的 HTML、Chromium `Bookmarks` JSON、Firefox 未压缩 JSON。Firefox `.jsonlz4` 请先从 Firefox 导出 HTML。先预览项目数量和目录，再确认在所选目录中建立一个新的导入文件夹。

原文件按原始字节保存并计算 SHA-256。未知字段、标签、图标、注释和高精度数字保留在原件或扩展元数据中；浏览器 API 只写入支持的标题、URL 和结构。URL 可能被浏览器规范化，实际值显示在详情中，原始输入仍在备份中。

HTML 导出为 UTF-8，排除回收站。完整项目 ZIP 包含：

- `project.json`：API 可见书签树、元数据、历史、快照、任务、结果、设置及原件索引。
- `originals/<来源ID>`：每份导入文件的精确字节；文件名、格式和 SHA-256 见索引。
- `README.txt`：备份格式说明。

导入项目 ZIP 时先校验原文件哈希，再预览。即使在同一个配置内，也采用创建新节点的恢复方式，不把旧 ID 当作写入目标。回收站标记和原目录位置映射到新节点；原目录缺失时使用当前导入区域。旧历史、快照和检测证据完整归档在导入的 ZIP 原件中，不将另一配置的撤销记录或检测状态激活为当前数据。需要查看旧版本时，可解压该原件阅读 `project.json`；要在原配置撤回本工具操作，使用「版本快照 → 回滚预览」。

单个输入文件最大 128 MiB，最多 200,000 个节点，JSON 目录深度最多 100 层。文件和备份通过 IndexedDB 暂存传输，避免把原始字节塞入 Chrome 的 JSON 消息。大文件解析、ZIP 压缩及完整历史读取仍受本机内存、磁盘与浏览器性能影响。

## 网页检测

选择选中项目、当前目录、全部书签或失败项重测。默认总并发 6、同主机最多 2、单次尝试超时 12 秒。先 HEAD；对于 400/403/404/405/406/501 使用 GET 复核，发送 `Range: bytes=0-65535`，用 BYOB 字节流累计读取最多 64 KiB 后取消正文。在不支持限定读取的流上，取得响应头后直接取消正文。网络栈可能提前缓冲数据，不能据此承诺线路上的总传输量严格只有 64 KiB。

| 状态 | 含义 |
| --- | --- |
| 正常 | 实际收到 2xx 响应 |
| 站点响应错误 | 实际收到 404、410、5xx 等 HTTP 响应 |
| 访问受限 | 401、403、429，可能是登录、权限或限流 |
| 连接异常 | 浏览器提供了实际网络错误原文，例如 `net::ERR_EMPTY_RESPONSE` |
| 无法确认 | 超时、缺少详细错误，或证据不足 |
| 已跳过 | 内网筛选、非 HTTP/HTTPS、URL 中含凭据、权限不足、取消或 URL 已变 |
| 结果已过期 | 当前节点 URL 与被测 URL 不一致 |

请求不携带站点 Cookie 或登录凭据，故登录后的可访问页面可能被标为访问受限。遵循浏览器适用的网络配置，不设置代理。默认跳过明确私有 IP、回环、链路本地、已知内网域名等；这不是严格的网络隔离，无法在请求前可靠识别所有 DNS 解析结果，也不能保证重定向不会指向内网。

队列每一短批和每个完成结果都会持久化。关闭工作台标签页不取消任务；关闭浏览器会停止执行，下次启动后通过启动事件、消息和 30 秒 alarms 继续。明确点击取消会持久保存取消状态；已发出的请求可能已经抵达站点。

超时、DNS 或连接错误不能直接确定责任在本地还是目标站点。没有可关联的浏览器错误时显示「未提供详细错误」，不编造错误码，不依据检测结果自动删除。
